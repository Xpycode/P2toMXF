# Code Review Report (2026-01-03 10:00:18)

## Scope
- Swift app sources under `P2toMXF/` (models, services, views, and app entry).

## Findings

### High
1) Audio mapping and timecode settings are ignored in the main conversion path.
- Evidence: `P2toMXF/Services/FFmpegWrapper.swift:168-247` routes conversions through `rewrapSingleClip`/`rewrapClipWithFFmpeg`, which always copies audio (`-c:a copy`) and never uses `settings.audioMapping`. The BMX path (`P2toMXF/Services/BMXWrapper.swift:74-117`) doesn’t apply `settings.preserveTimecode` or any audio mapping either.
- Impact: UI choices like “Stereo Mix”/“Mono” and possibly “Preserve TC” are no-ops for most conversions; users can’t trust settings.
- Recommendation: apply audio mapping/timecode in both FFmpeg and BMX paths (or disable unsupported options for those paths). If BMX can’t mix, consider FFmpeg-based remux for those modes or document the limitation in UI.

2) Security-scoped access is not persisted and output directories are not scoped during queue processing.
- Evidence: path-only persistence in `P2toMXF/Models/P2Clip.swift:186-229` and `P2toMXF/Models/P2Clip.swift:718-739`, and `ContentView.swift:25-33` + `ContentView.swift:375-383` call `startAccessingSecurityScopedResource()` without retaining bookmarks or calling `stopAccessing`. `QueueManager` only scopes the card path (`P2toMXF/Services/QueueManager.swift:433-438`) and never scopes the destination path.
- Impact: queued jobs restored after relaunch likely fail due to missing security-scoped access; also resource leaks from unbalanced start/stop calls.
- Recommendation: store security-scoped bookmarks for card/output URLs, resolve them on launch, and start/stop access around actual I/O. Ensure both input (card) and output directories are scoped for queue runs.

3) Individual outputs can overwrite existing files or collide within the same job.
- Evidence: per-clip output naming in `P2toMXF/Services/QueueManager.swift:510-520` uses `clip.displayName` without conflict checks. FFmpeg runs with `-y` in `P2toMXF/Services/FFmpegWrapper.swift:245-246` (force overwrite).
- Impact: duplicate clip names or pre-existing files can be silently overwritten, risking data loss.
- Recommendation: run per-clip conflict resolution (similar to `resolveFilenameConflict`) and/or remove `-y` unless the user opts into overwrites.

### Medium
4) Concat list paths are not escaped, breaking merges for paths containing single quotes.
- Evidence: `P2toMXF/Services/FFmpegWrapper.swift:358-363` writes `file '\(file.path)'` without escaping `'`.
- Impact: merge fails for clips or temp paths with apostrophes.
- Recommendation: escape single quotes for concat files or use an alternative concat method that avoids inline quoting issues.

5) Slow-speed warning UI can never be triggered.
- Evidence: `P2toMXF/Services/SpeedTracker.swift:184-214` provides `checkSpeed`, but `QueueManager` never calls it; `slowSpeedWarning` is only cleared (`P2toMXF/Services/QueueManager.swift:386-390`, `P2toMXF/Services/QueueManager.swift:486-489`).
- Impact: warning banner in the queue UI never appears even when speed is poor.
- Recommendation: call `checkSpeed` from progress callbacks (FFmpeg metrics) and assign `slowSpeedWarning` when thresholds are crossed.

6) Container validation fallback is effectively a stub when ffprobe is missing.
- Evidence: `P2toMXF/Services/VerificationService.swift:240-270` returns placeholder `ContainerInfo` without parsing stderr from `ffmpeg -i`.
- Impact: “Quick” verification may report success without actually validating container/streams when ffprobe is unavailable.
- Recommendation: parse stderr for format/stream details or downgrade the result to “unverified” when ffprobe isn’t available.

### Low
7) XML parsing errors are swallowed, silently dropping clips.
- Evidence: `P2toMXF/Services/P2CardParser.swift:53-56` uses `try?` and ignores failures.
- Impact: users may miss clips without any explanation.
- Recommendation: collect and surface parse errors (console log or UI warning), or fail fast with a clear error message.
