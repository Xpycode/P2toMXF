The Core Problem

Panasonic P2 cards store video and audio as separate MXF files (OPAtom format). Most tools, MAM systems, and broadcast servers expect single self-contained MXF or MOV files (OP1a). FFmpeg's MXF muxer fails on P2 AVC-Intra due to a frame-size padding mismatch.

Why FFmpeg Alone Fails

# FFmpeg calculates: 568,832 bytes/frame (from AVC-Intra spec) # P2 actual frames: 568,320 bytes/frame (Panasonic's padding) # Difference: 512 bytes [mxf @ 0x...] track 0: frame size does not match index unit size, 568320 != 568832

The P2toMXF Solution

P2 Card (OPAtom) BMX FFmpeg VIDEO/*.MXF ──┬── bmxtranswrap ─────▶ concat ───▶ Final AUDIO/*.MXF ──┘ -t op1a OP1a demuxer MXF/MOV (Panasonic-specific (stream copy, padding tables) fast)

The macOS Gap

On macOS, the P2 MXF tooling landscape is thin. MXF Wrapper only outputs MOV (no MXF OP1a). EditReady doesn't explicitly support P2 AVC-Intra. Panasonic P2CMS doesn't rewrap or merge. bmxtranswrap requires Homebrew, cmake, and building from source. QuickTime can't even play MXF.

P2toMXF is the only native macOS app that bundles BMX + FFmpeg, handles the full OPAtom-to-OP1a pipeline, supports both MXF and MOV output, and provides batch queue, verification, and multi-card loading — all without requiring a terminal.

Key Findings

BMX Is Invisible to Most Users

bmxtranswrap is the correct solution, universally recommended by MXF experts. But it lives on SourceForge, requires building from source, and has no GUI. People on Creative COW, Apple Community, Blackmagic Forum, DVXuser, and Adobe Community struggle with P2 MXF for years — but almost never discover it.

P2toMXF bridges this gap: a native macOS app wrapping the exact CLI pipeline that broadcast engineers use, made accessible to editors who would never open a terminal.

"MXF" Is Not One Format

Multiple posts reveal people being told "we support MXF" and then finding their P2 MXF rejected. Sony XDCAM MXF, Panasonic P2 MXF, and Avid MXF are effectively different formats sharing a file extension. The MXF "standard" has dozens of operational patterns, codec profiles, and metadata schemes — and tools that handle one variant often fail on another.

The Problem Persists Across Decades

Posts range from 2008 to 2025. Every major NLE has documented P2 import failures. Adobe has broken and re-broken P2 support across Premiere versions. The FFmpeg MXF muxer bugs remain open. This is not a problem that's going away.

Professional Broadcast Uses Dedicated Rewrapping

mxfSPEEDRAIL, Telestream Vantage, FFAStrans, and MyDMAM all have P2-to-OP1a conversion built into their ingest pipelines. Raw P2 cards are not directly usable in most broadcast workflows. P2toMXF provides the same capability as a standalone desktop tool.
